## 2. O problema em uma frase

Cache poisoning explora entradas não incluídas na cache key que influenciam a resposta armazenada e depois compartilhada com outros usuários.

## 3. O que você precisa dominar

- **Cache key** — Conjunto de atributos usados para distinguir objetos no cache.
- **Unkeyed input** — Entrada que altera a resposta sem participar da cache key.
- **HIT/MISS** — Indicadores de resposta servida do cache ou gerada na origem.
- **Vary** — Cabeçalho que pode ampliar os elementos considerados pelo cache.

## 4. Modelo mental / como funciona

1. Request chega com entrada variável
2. Backend usa essa entrada para montar a resposta
3. Cache calcula uma chave incompleta
4. Resposta alterada é armazenada
5. Novos usuários recebem a mesma resposta cacheada

## 5. Por que isso importa

Cache poisoning explora entradas não incluídas na cache key que influenciam a resposta armazenada e depois compartilhada com outros usuários.

Na prática, segurança não depende de decorar o nome da técnica. Ela depende de localizar a fronteira de confiança, identificar o dado ou estado que muda a decisão e provar, com evidência mínima, se o controle impede o comportamento indesejado.

Os pontos-chave desta aula devem ser usados como perguntas de revisão:

- Conjunto de atributos usados para distinguir objetos no cache.
- Entrada que altera a resposta sem participar da cache key.
- Indicadores de resposta servida do cache ou gerada na origem.

## 6. Exemplo técnico — Cache key incluindo dimensões relevantes

```ts
function cacheKey(req: RequestLike) {
  const url = new URL(req.url);
  const language = req.headers["accept-language"] ?? "default";

  return [
    req.method,
    url.host,
    url.pathname,
    url.search,
    language
  ].join("|");
}
```

A cache key precisa refletir tudo que muda materialmente o conteúdo compartilhado.

## 9. Como defender / corrigir

Garanta cache keys corretas, normalize headers, não cache respostas personalizadas e controle entradas refletidas.

A correção deve agir sobre a causa. Evite controles cosméticos como esconder IDs, renomear rotas, desativar mensagens sem corrigir a decisão ou confiar somente no frontend.

## 10. Como detectar / investigar

Compare respostas HIT/MISS, headers de cache e variações inesperadas da mesma URL entre usuários.

Uma detecção útil combina:

```text
identidade/host
+ ação
+ recurso/destino
+ horário
+ resultado
+ contexto
```

## Problema e competência verificável — AULA-046 (oficina A)

**Caso inédito:** Um site armazena /assets/help.css com versão de idioma pt-BR e en-US; uma implementação que omite idioma da chave entregaria representação errada.

**Decisão crítica:** cache key deve incorporar toda dimensão permitida que altere resposta, e ignorar cabeçalhos arbitrários como origem confiável.

**Hipótese que precisa ser refutada:** pt-BR e en-US geram chaves diferentes; resposta privada faz BYPASS.

**Evidência esperada:** sharedAssetCache(path='/assets/help.css',locale='pt-BR') produz chave distinta da variante en-US.

**Competência:** explicar a causa, prever observáveis, executar teste com entrada legítima e adversarial, selecionar a defesa e declarar os limites do teste.

### Mecanismo e exemplo resolvido

1. **Estado inicial:** Um site armazena /assets/help.css com versão de idioma pt-BR e en-US; uma implementação que omite idioma da chave entregaria representação errada.
2. **Entrada e fronteira:** cache key deve incorporar toda dimensão permitida que altere resposta, e ignorar cabeçalhos arbitrários como origem confiável.
3. **Decisão:** Normalize variações conhecidas no servidor; configure Vary/keys coerentes e não incorpore dados controlados não validados na resposta armazenada.
4. **Observação:** sharedAssetCache(path='/assets/help.css',locale='pt-BR') produz chave distinta da variante en-US.
5. **Interpretação:** pt-BR e en-US geram chaves diferentes; resposta privada faz BYPASS. Não confunda a evidência de um modelo isolado com exploração ou comprovação em produto de terceiros.

**Checkpoint 2 (observar):** Na saída JSON procure `normal` (controle positivo) e `hostile` (controle negativo); compare os campos e diga qual condição bloqueou ou isolou o risco.

**Checkpoint 3 (corrigir e retestar):** Normalize variações conhecidas no servidor; configure Vary/keys coerentes e não incorpore dados controlados não validados na resposta armazenada. Reexecute e registre também o caso legítimo para evitar uma "correção" que só desliga a função.

### Detecção, defesa, limites e fontes

- **O que procurar:** pt-BR e en-US geram chaves diferentes; resposta privada faz BYPASS.
- **Controle primário:** Normalize variações conhecidas no servidor; configure Vary/keys coerentes e não incorpore dados controlados não validados na resposta armazenada.
- **Controle de compatibilidade:** sharedAssetCache(path='/assets/help.css',locale='pt-BR') produz chave distinta da variante en-US.
- **Limitação honesta da evidência:** Simulador de chave e elegibilidade sem CDN, cache HIT real ou inspeção de header de resposta.
- **Referência técnica para leitura crítica:** https://portswigger.net/web-security/web-cache-poisoning
