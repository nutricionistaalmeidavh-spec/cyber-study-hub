## 2. Objetivo e mecanismo causal

Buffer overflow é escrita além da extensão de um objeto. Para um nome com capacidade cap, n bytes de texto exigem n+1 posições devido ao NUL. O contrato é n < cap e n ≤ bytes disponíveis na origem. São validações diferentes. Em um parâmetro `char dst[8]`, C ajusta a declaração para ponteiro: o 8 não garante que o chamador forneceu oito bytes. O contrato deve receber cap e ser cumprido pelo chamador.

## 4. Exemplo resolvido — estado, decisão e efeito

O arquivo overflow8.bin é N, 08, ABCDEFGH: dez bytes no total. O parser v1 testa n>8, portanto aceita 8. memcpy escreve índices 0..7 legalmente; a instrução seguinte escreve NUL no índice 8, primeiro byte fora de name. boundary7.bin contém sete caracteres, deixa índice 7 para NUL e funciona. truncated.bin declara quatro caracteres mas contém dois; isso viola a origem, independentemente do destino.

## 7. Código comentado e artefatos

```c
int copy_name(char *dst, size_t cap, const char *src, size_t n) {
    if (!dst || !src || cap == 0 || n >= cap) return -1;
    memcpy(dst, src, n); // origem também precisa oferecer n bytes
    dst[n] = '\0';      // garantido dentro do objeto por n < cap
    return 0;
}
```

## 8. Laboratório executável

Ambiente-base: Linux x86-64, Python 3.11+, compilador C11 GCC e binutils. Use cópia local; os programas são próprios e não acessam rede. Na raiz do pacote cumulativo:


O build fornece `make_fixtures.py`, arquivos em `fixtures/`, hashes em `fixtures/manifest.json` e executáveis em `build/`. Uma falha de geração ou compilação interrompe o runner. Ele verifica saídas reais, tem timeout e desativa core dumps. Os crashes deliberados ficam restritos aos processos de laboratório.

**Resultado esperado e checkpoints:** ASan v1: stack-buffer-overflow em name[n] para os dois inputs n=8. v2: retorno 2 com result=-1. n=0,3,7 continuam aceitos. O teste copy usa um destino real de quatro bytes e rejeita n=4; isso verifica o contrato sem supor capacidade pela assinatura.

Compare previsão e observação antes de avançar. Quando a atividade usa `run.py`, abra os logs em `build/logs/` e o JSON `build/results-<grupo>.json`: retorno do programa vulnerável e retorno do runner são coisas diferentes. A análise Python imprime JSON calculado sobre as fixtures disponíveis.

## 10. Defesa e reteste

O patch usa n>=sizeof name apenas porque name é array local visível. Em API extraída, receba cap. Reteste vazio, cap−1, cap, cap+1 e origem truncada. Não trunque silenciosamente nomes se isso puder fundir identidades distintas.

## 11. Troubleshooting específico

Um alerta “stack-buffer-overflow” não significa exaustão da stack. Se a linha for memcpy em vez do terminador, confira se você usou a fixture exata: um input maior pode disparar outro acesso.

## 14. Quiz

### 1. Com cap=8, maior nome C sem truncar?
A. 8 bytes
B. 7 bytes
C. 9 bytes
D. Depende apenas de sizeof(char*)

**Resposta:** B. O oitavo byte precisa guardar NUL.

### 2. Qual acesso falha para n=8 nesta fixture?
A. Leitura do cabeçalho
B. Primeiro byte do memcpy
C. Último byte do memcpy
D. Escrita name[8] do terminador

**Resposta:** D. A cópia de oito bytes cabe; o terminador exige o nono.

### 3. char dst[8] em parâmetro garante oito bytes?
A. Não, o parâmetro é ajustado para ponteiro
B. Sim, o compilador sempre valida o chamador
C. Somente com -O0
D. Somente se houver NUL

**Resposta:** A. O chamador precisa fornecer capacidade verdadeira por contrato.
