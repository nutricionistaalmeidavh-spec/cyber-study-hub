## 2. Capstone: ler notas sem entregar o sistema operacional ao renderer

Uma janela mostra duas ações: Alice lê a própria nota A ou tenta ler a nota B. O renderer não deve receber `fs`, `shell`, canais IPC arbitrários ou poder escolher sua identidade. O main, que possui capacidades do sistema operacional, precisa validar de onde veio o pedido, os argumentos e a autorização do usuário antes de devolver o conteúdo.

O projeto completo está em [electron](/course-labs/phase16-platform/electron/README.md): `main.cjs`, `preload.cjs`, `renderer.js`, `index.html`, `handler.cjs`, `test.cjs` e `package.json`. Ele é independente do frontend do Study Hub. A sessão Alice é uma fixture explicitamente mantida no main; não implementa um serviço de login.

## 3. Mecanismo: três contextos e uma fronteira de privilégios

O renderer executa DOM/JS e chama `window.notes.read(id)`. O preload isolado expõe essa única capacidade pelo contextBridge. A mensagem serializada chega ao handler `notes:read` no main. O handler valida WebContents/frame/URL, valida schema do argumento, recupera a identidade do estado confiável do main e verifica owner.

`contextIsolation` separa o contexto JavaScript do preload, mas não decide propriedade da nota. `nodeIntegration:false` retira Node do renderer; `sandbox:true` limita o processo. Nenhuma dessas opções substitui autorização do handler. A documentação Electron recomenda validar remetentes de IPC e reduzir APIs expostas. [Guia de segurança Electron](https://www.electronjs.org/docs/latest/tutorial/security).

O protocolo `course://app` entrega somente dois arquivos de uma lista finita. Caminhos arbitrários nunca viram `readFile` ou `net.fetch` diretamente. A janela bloqueia navegação, novas janelas e webviews; permissões são negadas. CSP impede script inline e recursos externos. O protocolo customizado evita depender de confiança ampla no esquema file.

## 4. Main, preload e handler completos

```javascript
'use strict';
const {app,BrowserWindow,ipcMain,protocol,net}=require('electron');
const path=require('node:path');
const {pathToFileURL}=require('node:url');
const {createReadHandler}=require('./handler.cjs');
protocol.registerSchemesAsPrivileged([{scheme:'course',privileges:{standard:true,secure:true,supportFetchAPI:true}}]);
const pageURL='course://app/index.html';
let win;
app.whenReady().then(async()=>{
  // Lista finita impede usar o protocolo como leitor arbitrário do filesystem.
  const files={'/index.html':'index.html','/renderer.js':'renderer.js'};
  protocol.handle('course',request=>{
    const u=new URL(request.url);
    const file=Object.hasOwn(files,u.pathname)?files[u.pathname]:null;
    if(u.host!=='app'||u.search||!file) return new Response('not found',{status:404});
    return net.fetch(pathToFileURL(path.join(__dirname,file)).href);
  });
  win=new BrowserWindow({width:650,height:400,webPreferences:{preload:path.join(__dirname,'preload.cjs'),nodeIntegration:false,contextIsolation:true,sandbox:true,webSecurity:true}});
  win.webContents.setWindowOpenHandler(()=>({action:'deny'}));
  win.webContents.on('will-navigate',e=>e.preventDefault());
  win.webContents.on('will-attach-webview',e=>e.preventDefault());
  win.webContents.session.setPermissionRequestHandler((_wc,_p,cb)=>cb(false));
  win.webContents.session.setPermissionCheckHandler(()=>false);
  // Login sintético explícito; app real usaria sessão verificada fora do renderer.
  const identities=new Map([[win.webContents.id,'alice']]);
  const wcId=win.webContents.id;
  ipcMain.handle('notes:read',createReadHandler(win,pageURL,id=>identities.get(id)));
  win.on('closed',()=>{identities.delete(wcId);ipcMain.removeHandler('notes:read');});
  await win.loadURL(pageURL);
});
app.on('window-all-closed',()=>app.quit());
```

```javascript
const {contextBridge,ipcRenderer}=require('electron');
// API de capacidade mínima: renderer não escolhe canal e não recebe event/IPC bruto.
contextBridge.exposeInMainWorld('notes',Object.freeze({read:id=>ipcRenderer.invoke('notes:read',{id})}));
```

```javascript
'use strict';
// Função de fronteira compartilhada pelo main e testes sem GUI.
exports.createReadHandler = (window, pageURL, identityFor) => (event,args) => {
  // Vincula objeto WebContents e frame principal, não apenas prefixo da URL.
  if (event.sender!==window.webContents || event.senderFrame!==window.webContents.mainFrame || event.senderFrame.url!==pageURL) {
    throw new Error('SENDER_DENIED');
  }
  if (!args || typeof args!=='object' || Array.isArray(args) || Object.keys(args).length!==1 || typeof args.id!=='string' || !/^[ab]$/.test(args.id)) {
    throw new Error('INVALID_ARGUMENT');
  }
  // Identidade vem do estado do main; nunca de args.owner enviado pelo renderer.
  const user=identityFor(event.sender.id);
  if (!user) throw new Error('UNAUTHENTICATED');
  const note={a:{owner:'alice',text:'nota A'},b:{owner:'bob',text:'nota B'}}[args.id];
  if (note.owner!==user) throw new Error('FORBIDDEN');
  return {text:note.text};
};
```

O renderer usa `textContent`, não `innerHTML`, para exibir o JSON e erros. A página completa e o renderer estão junto do projeto; não há bundler nem assets remotos. Não exponha `ipcRenderer` inteiro, um método `send(channel,payload)` genérico nem objetos de evento para a página.

### Exemplo resolvido

O usuário clica “Tentar B”. `notes.read('b')` chega do WebContents e frame corretos, com payload `{id:'b'}` válido. A identidade consultada no main é Alice; a fixture B pertence a Bob. O handler lança `FORBIDDEN`. O transporte IPC pode prefixar a mensagem com contexto de invocação; a palavra `FORBIDDEN` é o marcador estável.

Uma segunda janela com URL idêntica deve falhar antes disso: igualdade de URL não prova que o objeto WebContents está autorizado. Um iframe de mesma origem também é rejeitado por não ser `mainFrame`. Argumentos extras como `{id:'b',owner:'bob'}` falham no schema, e nem chegam a escolher identidade.

## 5. Laboratório sem GUI: testar a decisão usada pelo main

Pré-requisito: Node 22+. Nenhuma dependência precisa ser instalada para testar o handler.

```bash
cd public/course-labs/phase16-platform/electron
node --version
npm test
```

Esperado: 8 testes, 8 pass, 0 fail. Eles cobrem nota própria e reteste, owner alheio, identidade forjada por payload, WebContents diferente, subframe de mesma origem, navegação do frame principal, ausência de sessão e argumentos inválidos.

Esses testes usam dublês dos objetos de transporte e executam a função real chamada por `ipcMain.handle`. Confirmam as decisões da função, mas **não** confirmam isolamento Chromium, inicialização do preload, transporte IPC real nem GUI. Um mock que sempre retorna “denied” não é usado para decidir acesso.

**Checkpoint 1:** remova temporariamente, em uma cópia do `handler.cjs`, a linha `if (note.owner!==user) ...`, rode o mesmo teste e confirme que `owner alheio negado` falha. Restaure a linha e rode novamente. Sem essa mutação/reteste, passar testes positivos não demonstra a sensibilidade do gate ao defeito principal.

## 6. Laboratório de runtime: janela Electron

Pré-requisitos adicionais: desktop local com suporte à sandbox, dependência Electron instalada e acesso inicial ao registry/download. Use uma versão suportada na data de execução, conserve a versão exata e o lockfile gerados. A versão de runtime não é fornecida nem validada por esta edição offline; não trate a instalação abaixo como build bit a bit reproduzível antes de fixar o resultado.

```bash
npm install --save-dev --save-exact electron@latest
npm start
```

Não use `--no-sandbox` para conseguir uma captura em ambiente root/headless: isso alteraria a propriedade que se deseja observar. Se o desktop não existe, marque o teste pendente.

1. Clique **Ler A**. Esperado: `{"text":"nota A"}`.
2. Clique **Tentar B**. Esperado: mensagem contendo `FORBIDDEN` e nenhum conteúdo B.
3. Abra DevTools pelo menu da janela. Avalie `typeof require`: deve ser `undefined`. `Object.keys(window.notes)` deve listar somente `read`.
4. Execute `await window.notes.read('../../secret')`: rejeição `INVALID_ARGUMENT`.
5. Refaça **Ler A** para confirmar que o controle não quebrou o caso legítimo.

**Checkpoint 2:** explique por que `typeof require === 'undefined'` sozinho não impede ler B se o main aceitar qualquer ID. Ele mede disponibilidade Node no renderer; o defeito de owner é outra fronteira.

Os testes de canal desconhecido, iframe e navegação em runtime podem ser adicionados por harness de integração, mas não são atestados pelo teste Node. O handler só registra `notes:read`; erros de canal não registrado do Electron não equivalem a sucesso do check de owner.

## 7. Investigação, defesa e troubleshooting

No main, registre categoria de rejeição, identificador de janela e operação, evitando conteúdo de notas/tokens. Monitore mudanças de origem/frame e exposição de APIs privilegiadas. CSP bloqueia certas injeções, mas uma funcionalidade legítima exposta de forma ampla ainda pode ser abusada. A correção principal é verificar remetente, payload e autorização onde a capacidade privilegiada é executada.

`Cannot find module electron`: dependência ainda não instalada; `require` ausente no renderer é esperado. Página branca: revise logs do main, URL customizada, allowlist de arquivos e erros CSP; não relaxe CSP indiscriminadamente. Erro de preload pede verificar caminho absoluto e APIs compatíveis com preload sandboxed. Rodar como root ou sem display pode falhar antes do teste; registrar isso é diferente de provar que a sandbox está ativa.

A API devolve apenas conteúdo autorizado. Se futuramente houver gravação/exportação, o main deve controlar diretório e schema, evitando receber comandos de shell ou caminhos arbitrários. A fixture de sessão Alice precisa ser substituída por autenticação confiável fora do renderer, com expiração/revogação; o app de aula não declara resolver login desktop de produção.

Cleanup: feche a janela; o fechamento remove handler e identidade da memória. O laboratório não cria notas em disco, não escreve fora da pasta e não acessa serviços externos em runtime. Downloads de dependências são uma etapa separada.

## 8. Quiz

1. Um iframe da mesma URL envia IPC. Por que o handler nega?
A. Todo iframe é automaticamente sandboxed pelo contextBridge.
B. Igualdade de URL substitui autorização de frame.
C. O contrato aceita somente o objeto do frame principal autorizado.
D. IPC sempre autentica owner como Alice.

**Resposta:** C. Origem/URL semelhante não torna um subframe o remetente autorizado.

2. O renderer passa `{id:'b',owner:'bob'}`. O que acontece?
A. Schema rejeita campo extra; a identidade seria consultada no main, não no payload.
B. O main muda a sessão para Bob.
C. O preload assina owner automaticamente.
D. A nota B é liberada se contextIsolation estiver true.

**Resposta:** A. Dados do renderer não estabelecem identidade confiável.

3. Oito testes Node passaram. Qual afirmação ainda exige runtime Electron?
A. O handler recusa user ausente.
B. A comparação de owner nega B para Alice.
C. O schema recusa ID com barras.
D. O preload real está isolado e o renderer não dispõe de Node.

**Resposta:** D. Dublês de transporte não executam Chromium ou a configuração de janela.

## 9. Flashcards

- **contextBridge mínimo** → expõe uma operação específica, nunca IPC bruto ou canais arbitrários.
- **sender versus URL** → identidade do WebContents/frame complementa o endereço do documento.
- **Identidade no main** → estado de sessão confiável consultado pelo handler; não campo enviado pela página.
- **USING owner no IPC** → aqui é código explícito de autorização no main, sem equivalência automática com RLS.
- **Teste de handler** → confirma decisões da função; não certifica sandbox, CSP ou IPC real.
