## 2. O problema em uma frase

Request smuggling ocorre quando componentes HTTP interpretam limites de requisição de forma diferente, criando desincronização entre frontend e backend.

## 3. O que você precisa dominar

- **Content-Length** — Cabeçalho que informa o tamanho do corpo HTTP.
- **Transfer-Encoding** — Mecanismo alternativo de delimitação do corpo, como chunked.
- **Desync** — Divergência de parsing que desalinha a fronteira entre requisições.
- **Normalization** — Padronização consistente de mensagens entre proxies e backends.

## 4. Modelo mental / como funciona

1. Cliente envia HTTP
2. Proxy/frontend interpreta os delimitadores
3. Backend interpreta novamente a mensagem
4. Uma divergência de parsing desalinha a fila
5. Respostas ou requisições podem ser associadas ao contexto errado

## 5. Por que isso importa

Request smuggling ocorre quando componentes HTTP interpretam limites de requisição de forma diferente, criando desincronização entre frontend e backend.

Na prática, segurança não depende de decorar o nome da técnica. Ela depende de localizar a fronteira de confiança, identificar o dado ou estado que muda a decisão e provar, com evidência mínima, se o controle impede o comportamento indesejado.

Os pontos-chave desta aula devem ser usados como perguntas de revisão:

- Cabeçalho que informa o tamanho do corpo HTTP.
- Mecanismo alternativo de delimitação do corpo, como chunked.
- Divergência de parsing que desalinha a fronteira entre requisições.

## 6. Exemplo técnico — Normalização defensiva antes do backend

```js
function validateFraming(headers) {
  const hasCL = headers["content-length"] !== undefined;
  const hasTE = headers["transfer-encoding"] !== undefined;

  if (hasCL && hasTE) {
    throw new Error("Ambiguous HTTP message framing");
  }

  if (hasTE && headers["transfer-encoding"] !== "chunked") {
    throw new Error("Unsupported transfer encoding");
  }
}
```

A defesa reduz ambiguidades entre camadas em vez de tentar adivinhar qual parser está certo.

## 9. Como defender / corrigir

Use parsers consistentes, normalize requests, rejeite combinações ambíguas e reduza traduções HTTP/2→HTTP/1 desnecessárias.

A correção deve agir sobre a causa. Evite controles cosméticos como esconder IDs, renomear rotas, desativar mensagens sem corrigir a decisão ou confiar somente no frontend.

## 10. Como detectar / investigar

Procure respostas trocadas, erros intermitentes de parsing, filas desalinhadas e padrões anômalos nos proxies.

Uma detecção útil combina:

## Problema e competência verificável — AULA-045 (oficina A)

**Caso inédito:** Um gateway e um serviço interno discordam sobre o tamanho do corpo quando recebem Content-Length e Transfer-Encoding simultaneamente.

**Decisão crítica:** um limite de mensagem ambíguo pode dessicronizar parsers HTTP em cadeia.

**Hipótese que precisa ser refutada:** o validador rejeita framing conflitante ou duplicado antes do encaminhamento.

**Evidência esperada:** Content-Length:5 passa; Content-Length:5 junto com Transfer-Encoding:chunked falha.

**Competência:** explicar a causa, prever observáveis, executar teste com entrada legítima e adversarial, selecionar a defesa e declarar os limites do teste.

### Mecanismo e exemplo resolvido

1. **Estado inicial:** Um gateway e um serviço interno discordam sobre o tamanho do corpo quando recebem Content-Length e Transfer-Encoding simultaneamente.
2. **Entrada e fronteira:** um limite de mensagem ambíguo pode dessicronizar parsers HTTP em cadeia.
3. **Decisão:** Rejeitar framing ambíguo na borda, padronizar parsers e HTTP downgrades, nunca normalizar ambiguidades de forma diferente a jusante.
4. **Observação:** Content-Length:5 passa; Content-Length:5 junto com Transfer-Encoding:chunked falha.
5. **Interpretação:** o validador rejeita framing conflitante ou duplicado antes do encaminhamento. Não confunda a evidência de um modelo isolado com exploração ou comprovação em produto de terceiros.

### Detecção, defesa, limites e fontes

- **O que procurar:** o validador rejeita framing conflitante ou duplicado antes do encaminhamento.
- **Controle primário:** Rejeitar framing ambíguo na borda, padronizar parsers e HTTP downgrades, nunca normalizar ambiguidades de forma diferente a jusante.
- **Controle de compatibilidade:** Content-Length:5 passa; Content-Length:5 junto com Transfer-Encoding:chunked falha.
- **Limitação honesta da evidência:** Somente valida headers isolados; não envia payloads smuggling nem simula dois servidores em TCP.
