## 1. Situação realista e ligação com o roadmap

A revisão recebeu quatro achados sintéticos: injection via RAG, divulgação cruzada, agência excessiva e atualização de modelo sem integridade. Não basta colar uma lista Top 10: cada risco deve ligar ativo, fronteira, controle e teste.

Aula 206 é recomendada, nunca bloqueante.

**Ao concluir**, você será capaz de identificar o controle que tem autoridade, prever um caso permitido, negar uma variação adversarial segura, manter o caso permitido após a defesa e apresentar evidências sem alegar que a fixture é um sistema real.

## 2. Fundamentos que explicam a causa — não apenas nomes

**Fronteira de confiança:** Use a edição OWASP GenAI LLM Top 10 2026 e a OWASP Agentic 2026 como fontes. A fixture usa **rótulos conceituais**, não pretende listar todos os códigos/categorias oficiais nem substituir threat modeling.

**Falha que queremos reconhecer:** Uma planilha marca injection como mitigado por prompt, mas não apresenta teste negativo nem ponto de enforcement.

**Correção causal (onde o controle realmente atua):** Criar registro de risco com responsável, fronteira, impacto, mitigação causal, teste negativo e evidência. Risco sem prova continua aberto.

```text
ator e contexto confiável ──► orquestrador / dados não confiáveis
                                       │
                                       ▼
                          política / validação determinística
                           │                        │
                           ▼                        ▼
                        RECUSAR                ação mock permitida
                           └──────── log mínimo ────┘
                                        │
                                        ▼
                           evidência / reteste do positivo
```

Regra operacional: o LLM pode propor, mas não fornecer a sua própria identidade, conceder permissão de conta, transformar conteúdo RAG em tool call, validar hash de um arquivo não recebido ou provar que aprovou uma operação humana.

## 3. Exemplo técnico completo, local e previsível

**Passo 1.** Instale apenas Node.js 22+ (ou use o que já tem). Não é necessário instalar npm packages, login ou API key.

**Passo 2.** Na raiz do projeto, salve o JavaScript abaixo no arquivo `exemplo-207.mjs` e execute `node exemplo-207.mjs`. O arquivo `.mjs` permite imports ESM; não cole `import` estático no REPL tradicional.

```js
import {reviewRisk} from './public/course-labs/a201-210/models.mjs';
console.log(reviewRisk({risk:'prompt_injection',declaredBoundary:'retrieval',evidence:['untrusted-proposal-denied']}));
console.log(reviewRisk({risk:'prompt_injection',declaredBoundary:'retrieval',evidence:[]}));
```

**Passo 3.** Antes de rodar, preveja as decisões do contrato: 

| Variação de entrada | Saída esperada | Justificativa causal |
| --- | --- | --- |
| Caso 1 | `CONTROL_MAPPED` | Controle e prova declarados na fronteira certa. |
| Caso 2 | `EVIDENCE_MISSING` | Sem teste negativo não existe prova de mitigação. |
| Caso 3 | `BOUNDARY_MISMATCH` | Controle está no componente errado. |
| Caso 4 | `REQUIRES_MANUAL_MODELING` | Risco novo pede modelagem manual. |

O exemplo é mínimo para mostrar entrada e oráculo; o teste completo abaixo cobre esses cenários com assertions, incluindo bloqueios que não aparecem no snippet simplificado.

## 4. Laboratório guiado (não exige IA real)

**Arquivos:** [guia local](/course-labs/a201-210/README.md), [modelo de decisão](/course-labs/a201-210/models.mjs), [testes automatizados](/course-labs/a201-210/lab.test.mjs).

```bash

```

O teste **207** é obrigatório. Ele é um contrato de decisão em memória, não uma aplicação operacional.

1. **Baseline:** Consulte a publicação oficial de 2026 para não replicar taxonomia desatualizada.
2. **Variação negativa:** Crie quatro linhas de risco, cada qual com fronteira, controle e ID de teste.
3. **Observação:** Execute 207 removendo evidência e trocando a fronteira.
4. **Correção e reteste:** Reteste controles 202-206, distinguindo mapeamento conceitual de verificação de runtime.

Atenção a reteste duplo: **negação da ação indevida + manutenção da ação autorizada**. Não é suficiente negar tudo, nem confiar que a geração de texto pareça correta.

## 5. Como documentar evidência e implementar defesa

Crie `EVIDENCIAS-207.md` com entrada sintética, ator, ativo, contexto, versão do modelo de decisão, esperado, observado, hipótese, componente que decidiu, controle proposto, reteste e limites. Exemplo da estrutura:

```text
run_id: aula-207-local-01
asset: recurso fictício
actor: identidade de fixture
expected: decisão prevista
observed: resultado do teste Node
evidence: comando e saída (sem segredos)
root_cause: fronteira de confiança cruzada
fix: regra no componente com autoridade real
retest: bloqueio adversarial + caso permitido
limitation: fixture in-memory, não produto auditado
```

**Visão defensiva:** Criar registro de risco com responsável, fronteira, impacto, mitigação causal, teste negativo e evidência. Risco sem prova continua aberto.

**Detecção:** registre request ID, identidade fictícia, recurso e decisão, sem prompt completo, segredo, dados reais ou texto privado. Na implementação real, inclua logger com retenção/segurança apropriadas e revisão de autorização antes de persistir eventos.

**Stop condition:** teste apenas ambientes próprios, intencionalmente vulneráveis ou autorizados. Pare quando a hipótese estiver comprovada. Não aumente o impacto para «demonstrar melhor».

## 6. Avaliação de transferência — faça antes de abrir as respostas

Responda num segundo cenário que use **outros IDs fictícios** e uma permissão diferente; não copie apenas a saída do snippet.

1. Qual versão de OWASP consultar?
2. Uma taxonomia substitui ameaça específica?
3. Prompt sozinho impede tool abuse?
4. O que significa EVIDENCE_MISSING?
5. Como priorizar riscos distintos?

**Desafio:** formule um sexto teste negativo que altere só uma variável, declare saída esperada e explique qual componente deve impedir o abuso. Depois formule um teste positivo para não regredir.

**Rubrica (100 pontos):** conceito/fronteira 30; causa/controle 20; teste negativo 20; reteste funcional 20; limites/ética 10. Meta 80/100, sem ação fora do escopo.
