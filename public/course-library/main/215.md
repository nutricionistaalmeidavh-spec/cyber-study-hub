## Problema e objetivo verificável

**Fase:** Detecção. Uma consulta que alerta por todo 200 causará falso positivo em Alice; uma que alerta por todo 403 identifica bloqueios corretos, não acessos indevidos.

**Objetivo:** Criar uma detecção testável da leitura indevida simulada e compreender o papel distinto de Sigma, YARA, EDR e SIEM.

**Entrega:** `detections/ + TEST_CASES.md`, vinculada ao mesmo ativo `F001` do laboratório EscolaLab.

## Fundamentos e mecanismo causal

Sigma é uma linguagem de regra para eventos; YARA/YARA-X relaciona padrões de conteúdo de arquivos; EDR fornece telemetria de endpoint; SIEM correlaciona dados. Nesta aula executamos apenas uma função JS com eventos JSON, NÃO engines Sigma, YARA, EDR ou SIEM.

detectionRule verifica action read:F001, identity diferente de alice e status 200. Assim Bob 200 em vulnerable gera UNAUTHORIZED_READ_DEMO; Bob 403 após correção e Alice 200 não geram. Em sistemas reais o proprietário do objeto não pode ser nome fixo no código.

O fluxo completo é `escopo → inventário → hipótese → prova mínima → logs → detecção → correção → reteste → relatório`. Cada resultado desta aula deve referenciar entrada, esperado, observado e limite; a identidade `?as=` da aplicação é **simulada, não autenticação**.

## Exemplo resolvido — preveja antes de executar

Na raiz do repositório, salve o código como `exemplo-215.mjs` e execute `node exemplo-215.mjs`. Não use o REPL para imports estáticos. Os arquivos de código citados são do mesmo checkout do Hub; não instale dependências adicionais.

```js
import {decideRead,makeAuditEvent,detectionRule} from './public/course-labs/capstone-final/model.mjs';
for (const [actor,mode] of [['bob','vulnerable'],['bob','corrected'],['alice','corrected']]){
 const event=makeAuditEvent({actor,mode,result:decideRead({actor,mode})});
 console.log(actor,mode,event.status,detectionRule(event));
}
```

**Resultado esperado:** Somente bob/vulnerable: UNAUTHORIZED_READ_DEMO; os outros dois retornam null. Isso não prova qualidade de detector comercial.

**Contraprova/erro comum:** Uma regra com status===200 sem considerar dono produz falso positivo para Alice; documente essa contraprova e o risco de falso negativo se identidade/asset estiverem incorretos.

## Defesa, reteste e limites

**Controle e reteste:** detectionRule verifica action read:F001, identity diferente de alice e status 200. Assim Bob 200 em vulnerable gera UNAUTHORIZED_READ_DEMO; Bob 403 após correção e Alice 200 não geram. Em sistemas reais o proprietário do objeto não pode ser nome fixo no código.
