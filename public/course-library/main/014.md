# Aula 014 — CORS: política de leitura entre origens

**Trilha:** Web/AppSec Fundamentals · **Estado:** material aprofundado para avaliação editorial · **Modo:** estudo + prática local (Node.js 22+).  
**Escopo:** dados fictícios, loopback e modelos sem alvo externo; não são necessárias contas cloud, licença paga ou API externa.

## Problema e competência verificável

A API permite que a SPA https://painel.exemplo.test leia a resposta. A origem https://outro.exemplo.test e um domínio que termina com .evil.test não recebem Access-Control-Allow-Origin.

**Ao concluir, você deve conseguir:** Distinguir autorização backend de permissão de leitura em navegador e evitar reflexo indiscriminado de Origin. A resposta precisa demonstrar entrada, decisão, efeito, evidência e reteste; decorar a definição não é suficiente.

## Vocabulário sem pressupostos

1. Origin: esquema, host e porta da página de origem.
2. Preflight: requisição OPTIONS que verifica regras para certos métodos/headers.
3. Vary: Origin: indica a caches que a resposta pode variar conforme Origin.

## Mecanismo: da entrada à decisão

CORS é aplicado pelo navegador; curl e Node podem ver uma resposta que o script de outra origem não consegue ler. Headers CORS não autenticam pessoas. Cookies cross-site e credentials requerem política deliberada; '*' não combina com resposta credenciada.

**Fronteira de confiança:** a entrada controlada pelo cliente não pode modificar política interna só por estar bem formatada. Pergunte *quem decide, com quais dados confiáveis, antes de que efeito*. Primeiro registre um caso normal, depois altere uma variável e por fim reteste a correção.

### Exemplo comentado

```js
const origin='https://painel.exemplo.test';
if(allowed.has(origin)) headers['Access-Control-Allow-Origin']=origin;
headers['Vary']='Origin';
```

**Interpretação:** Origem exata recebe allow-origin e Vary; duas origens diferentes não recebem allow-origin. Compare com o objetivo legítimo; não confunda retorno HTTP, presença de dado no cliente e autorização de uso do dado.

### Análise de falha e recuperação

- **Erro comum:** Resposta HTTP 200 observada fora do navegador não significa que CORS liberou a leitura pelo script da página.
- **Se o teste não roda:** confira diretório, Node e dependências locais da suíte (somente para 015/020 use npm ci). Não altere várias condições simultaneamente.
- **Se o negativo falha como esperado:** o valor é provar que nenhum efeito indevido ocorreu; exceção genérica sem verificação de estado não encerra o estudo.
- **Limite experimental:** uma simulação em memória não substitui navegador real, proxy real, banco concorrente ou infraestrutura federada. Documente a lacuna antes de usar a conclusão em produção.
