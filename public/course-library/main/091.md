## 7. Exemplo técnico — Pipeline conceitual de decisão

```python
def classify(sample):
    if sample.reputation == "known_bad":
        return "block"
    if sample.signature_match:
        return "block"
    if sample.heuristic_score >= 80:
        return "analyze"
    return "allow_with_telemetry"

```

## 11. Como corrigir / reduzir risco

Mantenha mecanismos atualizados, habilite proteção em tempo real e proteja configuração contra alteração não autorizada.

### Controle primário vs compensatório

O controle primário deve corrigir a decisão insegura. Logging, WAF, alerta, rate limit ou EDR podem ser importantes, mas não devem ser vendidos como substitutos da correção quando a causa está no código/configuração.

## 13. Erros comuns de raciocínio

### Caso profissional e fronteira de confiança

Um arquivo corporativo recém-compilado não tem reputação conhecida, nenhuma assinatura detectada e score 20. Outro artefato fictício aparece como knownBad no catálogo local. A equipe deve classificar ambos sem presumir que 'desconhecido' significa perigoso.

**Mecanismo:** A decisão combina precedência dos indicadores, saúde do sensor e tolerância a incerteza. knownBad/assinatura confirmada pode levar a block; score >=80 pede review, enquanto ausência de confirmação com sensor íntegro pede allow_monitor.

**Armadilha a reconhecer:** Bloquear qualquer objeto não catalogado elimina software legítimo; permitir um objeto conhecido ruim porque seu score é baixo inverte a prioridade do controle.
