# Aula 209 — Definição do laboratório final

**Trilha:** Projeto final / Capstone  
**Revisão:** A técnico-editorial assistida por IA (não nota de aluno)  
**Tempo sugerido:** 60–100 minutos  
**Ambiente obrigatório:** Node.js 22+, laboratório sintético local R$ 0, sem conta externa.

## 1. Situação realista e ligação com o roadmap

O capstone geral começa por SCOPE.md e LAB_ARCHITECTURE.md, independentemente de a trilha de IA ter sido cursada. Exemplo acessível: notas locais com duas contas fake e dataset sintético.

Aula 208 (capstone IA) é **opcional**; este capstone geral é independente.

**Ao concluir**, você será capaz de identificar o controle que tem autoridade, prever um caso permitido, negar uma variação adversarial segura, manter o caso permitido após a defesa e apresentar evidências sem alegar que a fixture é um sistema real.

## 2. Fundamentos que explicam a causa — não apenas nomes

**Fronteira de confiança:** Autorização formal, lista finita de alvos, exclusões, dados fictícios, condições de parada e reset devem existir antes do experimento. Uma decisão `SCOPE_APPROVED_FIXTURE` não é permissão legal para testar terceiros.

**Falha que queremos reconhecer:** Uma URL externa entra por engano no escopo, ou um aluno usa dados reais sem permissão e sem mecanismo de reset.

**Correção causal (onde o controle realmente atua):** Declarar ambiente próprio, alvos localhost/fixture, owner autorizador, dados 100% sintéticos, stop condition e reset repetível.

```text
ator e contexto confiável ──► orquestrador / dados não confiáveis
                                       │
                                       ▼
                          política / validação determinística
                           │                        │
                           ▼                        ▼
                        RECUSAR                ação mock permitida
                           └──────── log mínimo ────┘
                                        │
                                        ▼
                           evidência / reteste do positivo
```

Regra operacional: o LLM pode propor, mas não fornecer a sua própria identidade, conceder permissão de conta, transformar conteúdo RAG em tool call, validar hash de um arquivo não recebido ou provar que aprovou uma operação humana.

## 3. Exemplo técnico completo, local e previsível

**Passo 1.** Instale apenas Node.js 22+ (ou use o que já tem). Não é necessário instalar npm packages, login ou API key.

**Passo 2.** Na raiz do projeto, inicie `node` para abrir o REPL e cole o JavaScript abaixo. Se preferir, salve como `exemplo-209.mjs` na raiz e use `node exemplo-209.mjs`.

```js
import {validateLabScope} from './public/course-labs/a201-210/models.mjs';
const s={owner:'aluno',authorization:{owner:'aluno',explicit:true},targets:['localhost:3000','fixture:rag'],
stopCondition:'evidência suficiente',dataKind:'synthetic',resetPlan:'node --test'};
console.log(validateLabScope(s));
console.log(validateLabScope({...s,targets:['https://fora-do-lab.invalid']}));
```

**Passo 3.** Antes de rodar, preveja as decisões do contrato: 

| Variação de entrada | Saída esperada | Justificativa causal |
| --- | --- | --- |
| Caso 1 | `SCOPE_APPROVED_FIXTURE` | Escopo próprio, local e reversível. |
| Caso 2 | `OUT_OF_SCOPE` | Alvo externo fora do permitido. |
| Caso 3 | `AUTHORIZATION_MISSING` | Não há correspondência entre dono e autorizador. |
| Caso 4 | `SAFETY_PLAN_MISSING` | Sem parada/reset não executar. |

O exemplo é mínimo para mostrar entrada e oráculo; o teste completo abaixo cobre esses cenários com assertions, incluindo bloqueios que não aparecem no snippet simplificado.

## 4. Laboratório guiado (não exige IA real)

**Arquivos:** [guia local](/course-labs/a201-210/README.md), [modelo de decisão](/course-labs/a201-210/models.mjs), [testes automatizados](/course-labs/a201-210/lab.test.mjs).

```bash
node --test public/course-labs/a201-210/lab.test.mjs
```

O teste **209** é obrigatório. Ele é um contrato de decisão em memória, não uma aplicação operacional.

1. **Baseline:** Entregue SCOPE.md com dono, autorização, dados, alvos, objetivos, exclusões, stop conditions e observações.
2. **Variação negativa:** Entregue LAB_ARCHITECTURE.md com fluxo, identidades fake, local dos artefatos e reset.
3. **Observação:** Rode o gate 209 com alvo externo e autorização divergente; explique cada recusa.
4. **Correção e reteste:** Passe os dois arquivos a revisor e comprove reprodução do estado-base sem contato com sistemas reais.

Atenção a reteste duplo: **negação da ação indevida + manutenção da ação autorizada**. Não é suficiente negar tudo, nem confiar que a geração de texto pareça correta.

## 5. Como documentar evidência e implementar defesa

Crie `EVIDENCIAS-209.md` com entrada sintética, ator, ativo, contexto, versão do modelo de decisão, esperado, observado, hipótese, componente que decidiu, controle proposto, reteste e limites. Exemplo da estrutura:

```text
run_id: aula-209-local-01
asset: recurso fictício
actor: identidade de fixture
expected: decisão prevista
observed: resultado do teste Node
evidence: comando e saída (sem segredos)
root_cause: fronteira de confiança cruzada
fix: regra no componente com autoridade real
retest: bloqueio adversarial + caso permitido
limitation: fixture in-memory, não produto auditado
```

**Visão defensiva:** Declarar ambiente próprio, alvos localhost/fixture, owner autorizador, dados 100% sintéticos, stop condition e reset repetível.

**Detecção:** registre request ID, identidade fictícia, recurso e decisão, sem prompt completo, segredo, dados reais ou texto privado. Na implementação real, inclua logger com retenção/segurança apropriadas e revisão de autorização antes de persistir eventos.

**Stop condition:** teste apenas ambientes próprios, intencionalmente vulneráveis ou autorizados. Pare quando a hipótese estiver comprovada. Não aumente o impacto para «demonstrar melhor».

## 6. Avaliação de transferência — faça antes de abrir as respostas

Responda num segundo cenário que use **outros IDs fictícios** e uma permissão diferente; não copie apenas a saída do snippet.

1. Quais entregáveis exatos?
2. O que torna o alvo permitido?
3. Por que stop condition vem antes do teste?
4. O que fica fora do relatório?
5. O que prova resetabilidade?

**Desafio:** formule um sexto teste negativo que altere só uma variável, declare saída esperada e explique qual componente deve impedir o abuso. Depois formule um teste positivo para não regredir.

**Rubrica (100 pontos):** conceito/fronteira 30; causa/controle 20; teste negativo 20; reteste funcional 20; limites/ética 10. Meta 80/100, sem ação fora do escopo. O gabarito fica separado para que seja possível avaliar sem spoiler: [Gabarito AULA-209](/course-labs/a201-210/answer-keys/AULA-209.md).

## 7. Acesso e limites de validade

**Núcleo obrigatório R$ 0:** Node.js 22, textos markdown, fixtures de decisão, testes Node; toda a atividade roda offline depois de obter os arquivos.

**Extensão optativa:** Inclua no SCOPE: finalidade, contato do dono, inclusão/exclusão, limites horários, dados sintéticos, hipóteses, critérios de parada e plano de descarte. Em LAB_ARCHITECTURE descreva browser, backend fake, data store e fronteiras.

Este contrato não comprova segurança operacional de LLMs reais, pipelines RAG com embeddings, banco/vetores de produção, assinaturas, credenciais/JWT, aprovação humana de verdade ou aprendizado validado com estudantes. A classificação A é uma **revisão editorial assistida por IA**, condicionada à QA da branch e sem ensaio humano.

**Leitura de referência:** https://csrc.nist.gov/pubs/sp/800/115/final. Projeto OWASP GenAI 2026: https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/. Não confunda a taxonomia da edição 2025 com a edição 2026.


## 8. Artefatos obrigatórios do capstone — modelos preenchíveis
### SCOPE.md
```md
# Escopo e autorização
Owner: aluno, ambiente próprio
Alvos inclusos: fixture:rag, localhost:3000
Excluídos: domínios públicos, rede corporativa, dados reais
Hipótese: Alice não acessa dados da conta Bob
Evidência: saída de teste e timestamp
Condição de parada: uma prova suficiente
Reset: comando de reinicialização das fixtures
```
### LAB_ARCHITECTURE.md
```text
Alice/Bob (dados fake) → app localhost → política → nota in-memory
                                      ↘ log mínimo
```
Indique o responsável por cada fronteira, o comando de reset e como provar que não há conexão de rede externa.
