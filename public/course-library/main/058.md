## 2. Visão geral

Same-Origin Policy restringe interações entre origens; CORS é o mecanismo controlado para relaxar parte dessas restrições.

## 3. Aprofundamento: o que realmente está acontecendo

Same-Origin Policy é uma regra do navegador. CORS é uma forma controlada de relaxar leitura cross-origin. Nenhum dos dois substitui autenticação/autorização server-side.

## 6. Fluxo técnico

1. **Página possui uma origin**
2. **JavaScript tenta acessar outra origin**
3. **Navegador aplica SOP**
4. **Servidor pode responder com política CORS**
5. **Browser decide se expõe a resposta ao script**

## 7. Exemplo técnico — Allowlist CORS explícita

```ts
const origins = new Set(["https://app.exemplo.com"]);

function corsOrigin(origin?: string) {
  if (!origin) return false;
  if (!origins.has(origin)) throw new Error("Origin não permitida");
  return origin;
}
```

### Como ler o exemplo

Evite refletir qualquer Origin automaticamente, especialmente com credenciais.

## 8. Por que a vulnerabilidade/mecanismo acontece

Same-Origin Policy é a regra do navegador; CORS é um mecanismo controlado pelo servidor para relaxar parte dessa regra. CORS não substitui autenticação nem autorização.

Não memorize apenas “payloads” ou comandos. A mesma classe de problema reaparece em frameworks e ferramentas diferentes quando a **mesma suposição** é quebrada.

## 11. Como corrigir / reduzir risco

Use allowlist explícita, não reflita Origin indiscriminadamente e evite credenciais com políticas amplas.

### Controle primário vs compensatório

O controle primário deve corrigir a decisão insegura. Logging, WAF, alerta, rate limit ou EDR podem ser importantes, mas não devem ser vendidos como substitutos da correção quando a causa está no código/configuração.

## 18. Oficina A — CORS e Same-Origin Policy

**Objetivo mensurável:** Identificar diferença entre resposta HTTP do servidor, leitura permitida pelo navegador e credenciais enviadas.

### Situação profissional e pré-requisitos

O frontend confiável está em `https://app.local` e a API em `https://api.local`. Uma segunda origem `https://evil.local` tenta ler a resposta usando JavaScript. Responder 200 não implica que navegador autorize a leitura.

Para começar, identifique o ator, o dado controlável, o componente que decide, o recurso afetado e o resultado que realmente pode ser observado. Não atribua ao laboratório funções de produção. Refaça a distinção entre hipótese, evidência e interpretação antes de qualquer mudança no controle.

### Mecanismo: acompanhe o dado até a decisão

Same-Origin Policy define limites de leitura entre scheme, host e port. CORS é política comunicada pelo servidor por headers, aplicada por navegadores compatíveis. Enviar cookies depende de credenciais, atributos de cookie e política do navegador; `Access-Control-Allow-Origin:*` não pode autorizar leitura com credenciais. CORS não protege recursos contra clientes fora do navegador.

**Exemplo resolvido.** `corsPolicy("https://app.local",true)` devolve origem exata, `Access-Control-Allow-Credentials:true` e `Vary:Origin`. `evil.local` e origem literal `null` não recebem ACAO.

**Questão de compreensão:** em qual momento a entrada deixa de ser mero dado e passa a interferir em uma decisão? Formule uma frase citando o objeto exato, a condição de falha e a observação esperada. Não confunda a explicação de mecanismo com uma prova de exploração.

5. Não modifique proteções do host nem use credenciais reais. Um resultado de teste automático não substitui teste end-to-end no navegador ou revisão de integração real.
