## 2. Objetivo e mecanismo causal

Segurança de memória exige três invariantes: objeto vivo, acesso dentro de sua extensão e tipo/alinhamento compatíveis. Uma entrada pode violar o comprimento sem mudar o ponteiro; free pode invalidar um ponteiro sem mudar seu valor numérico. O primeiro caso é espacial, o segundo temporal. O parser próprio fornece uma escrita fora do array e uma leitura fora da alocação; lab.c fornece uso após free. O diagnóstico classifica a violação, mas não estabelece automaticamente explorabilidade.

## 4. Exemplo resolvido — estado, decisão e efeito

Em N 08 ABCDEFGH, size=10, n=8 e name ocupa oito bytes. O teste n>8 passa, a cópia ocupa [0,7] e NUL tenta índice 8. Em R 08 X, size=3 e o corpo tem um byte; 2+n=10 aponta além da alocação de três bytes. No UAF, objeto de quatro bytes está vivo antes de free e morto depois: alias[0] seria inválido mesmo com índice zero. Logo, corrigir só o índice não resolve lifetime.

## 7. Código comentado e artefatos

```c
if (size < 2) return -1; // garante que size-2 não sofre underflow
size_t n = data[1];
if (n >= sizeof name || n > size - 2) return -1;
memcpy(name, data + 2, n); // corpo suficiente e destino com espaço
name[n] = '\0';         // terminador ainda pertence ao objeto
```

O trecho destaca a decisão da aula. Os programas completos, imports, entradas e build estão no [laboratório phase16-memory](/course-labs/phase16-memory/README.md). Use a pasta correspondente dentro do pacote do curso; trechos isolados não substituem as fontes completas.

## 8. Laboratório executável

Ambiente-base: Linux x86-64, Python 3.11+, compilador C11 GCC e binutils. Use cópia local; os programas são próprios e não acessam rede. Na raiz do pacote cumulativo:

```bash
cd public/course-labs/phase16-memory
python3 run.py build
python3 run.py parser
python3 run.py heap
```

O build fornece `make_fixtures.py`, arquivos em `fixtures/`, hashes em `fixtures/manifest.json` e executáveis em `build/`. Uma falha de geração ou compilação interrompe o runner. Ele verifica saídas reais, tem timeout e desativa core dumps. Os crashes deliberados ficam restritos aos processos de laboratório.

**Resultado esperado e checkpoints:** Encontre stack-buffer-overflow, heap-buffer-overflow e heap-use-after-free em logs separados. O conjunto não depende de um gerador ausente: make_fixtures.py é executado com retorno verificado no build. parser-v2 rejeita entradas inválidas; heap-fixed preserva saved=42.

Compare previsão e observação antes de avançar. Quando a atividade usa `run.py`, abra os logs em `build/logs/` e o JSON `build/results-<grupo>.json`: retorno do programa vulnerável e retorno do runner são coisas diferentes. A análise Python imprime JSON calculado sobre as fixtures disponíveis.

## 10. Defesa e reteste

Para violação espacial, valide extensão antes do acesso; para violação temporal, altere ownership e ordem de uso/liberação. Reteste com o mesmo arquivo e inclua caso válido. ASLR/NX podem limitar efeitos de uma falha, mas não restauram o contrato de objetos.

## 11. Troubleshooting específico

Se o programa simplesmente termina por sinal, abra o log completo antes de classificar. Diagnóstico de shadow memory indisponível é falha de ambiente, não confirmação da hipótese. Use builds non-PIE de análise definidos pelo runner.

## 13. Desafio e entrega

Classifique cada caso por espaço/tempo, leitura/escrita e local do objeto. Explique por que stack e heap descrevem localização, não severidade.

Entregue comando completo, versão do compilador/Python, hash ou identificação da fixture, resultado esperado e observado, evidência da correção e uma limitação. Separe hipótese de resultado executado.

## 14. Quiz

### 1. alias[0] após free viola qual invariante?
A. Índice positivo
B. Tamanho do cabeçalho
C. Lifetime do objeto
D. Permissão executável

**Resposta:** C. O objeto já morreu; índice zero não torna o acesso válido.

### 2. OOB read no ramo R ocorre em qual objeto?
A. Alocação de entrada criada pelo driver
B. Array name da stack
C. Variável n
D. Código executável

**Resposta:** A. driver aloca exatamente size bytes; data[10] excede a alocação de três.

### 3. Qual conclusão é sustentada pelo ASan?
A. Execução arbitrária
B. Exfiltração real
C. Severidade crítica universal
D. Acesso inválido no caminho executado

**Resposta:** D. Explorabilidade e impacto precisam de evidência adicional.
