# Aula 213 — Exploração controlada e prova de impacto

**Trilha:** Projeto Final Integrado / Capstone geral (não apenas IA)  
**Revisão:** A técnico-editorial assistida por IA; não certificação ou nota de aluno  
**Tempo sugerido:** 60–100 minutos  
**Pré-requisito recomendado (não bloqueante):** aulas 209–210; escopo aprovado e threat model.  
**Núcleo obrigatório:** R$ 0, Node.js 22+, arquivos locais e fixtures sintéticas; sem conta, cloud, API, GPU ou assinatura.

## Problema e objetivo verificável

**Fase:** Prova mínima. Exibir dados de um recurso sem necessidade aumenta o risco e não melhora o diagnóstico: a diferença entre status 200 e 403 já satisfaz a hipótese didática.

**Objetivo:** Provar o efeito de uma falha intencional de autorização sem obter dados reais nem ampliar impacto.

**Entrega:** `EVIDENCE_LOG.md`, vinculada ao mesmo ativo `F001` do laboratório EscolaLab.

## Fundamentos e mecanismo causal

Prova de conceito mínima confirma mecanismo causal com variação de uma condição. No EscolaLab, a identidade é um rótulo de fixture e a fatura F001 é fictícia; a saída não é prova de exfiltração ou pentest externo.

A decisão da função é suficiente para mostrar Bob 200 no modo vulnerable e Bob 403 no corrected. Não há necessidade de executar exploit, credenciais ou expor o servidor a outras interfaces.

O fluxo completo é `escopo → inventário → hipótese → prova mínima → logs → detecção → correção → reteste → relatório`. Cada resultado desta aula deve referenciar entrada, esperado, observado e limite; a identidade `?as=` da aplicação é **simulada, não autenticação**.

## Exemplo resolvido — preveja antes de executar

Na raiz do repositório, salve o código como `exemplo-213.mjs` e execute `node exemplo-213.mjs`. Não use o REPL para imports estáticos. Os arquivos de código citados são do mesmo checkout do Hub; não instale dependências adicionais.

```js
import {decideRead} from './public/course-labs/capstone-final/model.mjs';
const before=decideRead({actor:'bob',mode:'vulnerable'});
const after=decideRead({actor:'bob',mode:'corrected'});
console.log({before:before.status,after:after.status,stopped:true});
console.log({alice:decideRead({actor:'alice'}).status});
```

**Resultado esperado:** Bob 200→403 e Alice 200; evidência registra apenas metadados/códigos, com condição de parada satisfeita.

**Contraprova/erro comum:** Não repita solicitações para IDs desconhecidos para 'aumentar o impacto'; não teste dados de clientes nem associe Bob fictício a uma pessoa real.

**Arquivos reais:** [guia e preparação](/course-labs/capstone-final/README.md), [modelo de decisão](/course-labs/capstone-final/model.mjs), [servidor exclusivamente local](/course-labs/capstone-final/server.mjs), [testes do capstone](/course-labs/capstone-final/lab.test.mjs).
```bash
node --test public/course-labs/capstone-final/lab.test.mjs
node --test public/course-labs/capstone-final/grade-a-211-218.test.mjs
```

Os testes usam **uma fatura sintética de 15000 centavos**. O segundo arquivo cobre especificamente as invariantes 211–218. Se executar o servidor manualmente, ele escuta apenas `127.0.0.1:4191`; não abra firewall, exponha a porta nem copie autenticação fictícia para produto real.

1. **Etapa 1:** Vincule H2/H3 às mesmas versões e ao ativo LAB-F001; defina stop condition: primeira prova suficiente.
2. **Etapa 2:** Rode a função local em memória e salve só códigos, ator fictício, modo, instante, comando e hash/versão do código.
3. **Etapa 3:** Identifique causa (ausência de checagem owner em vulnerable), impacto restrito à fixture e efeito do controle corrigido.
4. **Etapa 4:** Registre consequência defensiva: aplicar autorização objeto-a-objeto e auditar leitura indevida; encaminhe eventos à aula 214.

**Qualidade mínima:** Um único par antes/depois com mesma entrada, origem, versão, instante e parada explícita; Alice não perde acesso.

## Defesa, reteste e limites

**Controle e reteste:** A decisão da função é suficiente para mostrar Bob 200 no modo vulnerable e Bob 403 no corrected. Não há necessidade de executar exploit, credenciais ou expor o servidor a outras interfaces.

**Critérios de parada e ética:** Não repita solicitações para IDs desconhecidos para 'aumentar o impacto'; não teste dados de clientes nem associe Bob fictício a uma pessoa real. Somente ativos próprios/intencionalmente vulneráveis/autorizados, sem dados pessoais e sem credenciais reais.

**Limites:** passar nesse teste prova apenas o contrato determinístico deste miniapp. Não prova autenticação, proteção de aplicações reais, SIEM/EDR, conformidade, desempenho, certificação ou qualidade pedagógica com estudantes. A revisão A é editorial assistida por IA; teste com aluno humano não foi realizado. Serviços comerciais são opcionais e nunca necessários.
