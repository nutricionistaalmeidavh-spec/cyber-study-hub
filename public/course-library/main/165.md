## 2. Objetivo e mecanismo causal

Heap fornece objetos com lifetime explícito: malloc cria uma alocação, free a encerra. O endereço não carrega informação suficiente sobre validade; aliases podem continuar guardando o mesmo número após liberação. Estado do allocator, redzones e reutilização variam por implementação. Não é necessário adivinhar metadados internos para demonstrar um uso após free: basta reconstruir ownership e a ordem de operações.

## 4. Exemplo resolvido — estado, decisão e efeito

malloc(4) cria bytes [0,3]; p[0]=42 inicializa o primeiro. alias=p cria segunda referência ao mesmo objeto, sem duplicá-lo. free(p) muda o estado para liberado. alias[0] tenta ler índice válido geometricamente, mas objeto inválido temporalmente. No patch, value=p[0] ocorre ainda vivo; depois free(p), p=NULL e a impressão usa o valor copiado 42. Zerar apenas p sem tratar alias não corrige acessos por alias.

## 7. Código comentado e artefatos

```c
unsigned char *p = malloc(4);
if (!p) return 70;     // falha de alocação não é objeto válido
p[0] = 42;
unsigned value = p[0]; // leitura enquanto o objeto está vivo
free(p);
p = NULL;             // evita reuso acidental pelo dono
printf("saved=%u\n", value); // usa cópia, não memória liberada
```

## 8. Laboratório executável

Ambiente-base: Linux x86-64, Python 3.11+, compilador C11 GCC e binutils. Use cópia local; os programas são próprios e não acessam rede. Na raiz do pacote cumulativo:

```bash
cd public/course-labs/phase16-memory
python3 run.py build
python3 run.py heap
```

O build fornece `make_fixtures.py`, arquivos em `fixtures/`, hashes em `fixtures/manifest.json` e executáveis em `build/`. Uma falha de geração ou compilação interrompe o runner. Ele verifica saídas reais, tem timeout e desativa core dumps. Os crashes deliberados ficam restritos aos processos de laboratório.

**Resultado esperado e checkpoints:** uaf.txt contém heap-use-after-free, stack de alocação, liberação e uso. heap-fixed.txt mostra saved=42 owner_null=1 e saída 0. Identifique as três linhas de origem; um ponteiro não nulo antes do uso não seria validação suficiente.

Compare previsão e observação antes de avançar. Quando a atividade usa `run.py`, abra os logs em `build/logs/` e o JSON `build/results-<grupo>.json`: retorno do programa vulnerável e retorno do runner são coisas diferentes. A análise Python imprime JSON calculado sobre as fixtures disponíveis.

## 10. Defesa e reteste

Defina um dono responsável por liberar, restrinja empréstimos ao lifetime do dono e extraia dados necessários antes de free. Reteste ausência de leitura tardia e valor preservado. Em código maior, procure callbacks ou filas que guardam aliases além da liberação.

## 11. Troubleshooting específico

Sem ASan, o valor antigo pode parecer continuar 42; isso não torna o acesso válido. Otimizações podem mudar esse comportamento. Não trate offsets de redzones ou layout de um allocator como ABI universal.

## 13. Desafio e entrega

Desenhe os estados vivo/liberado e marque p e alias em cada transição. Proponha uma API que impossibilite a fila guardar referência após o dono liberar.

Entregue comando completo, versão do compilador/Python, hash ou identificação da fixture, resultado esperado e observado, evidência da correção e uma limitação. Separe hipótese de resultado executado.

## 14. Quiz

### 1. p=NULL invalida automaticamente alias?
A. Sim, são o mesmo nome
B. Somente após malloc
C. Não; alias é outra variável com o endereço antigo
D. Somente em 64 bits

**Resposta:** C. Modificar uma variável ponteiro não modifica outras cópias.

### 2. Como preservar 42 com segurança?
A. Copiar o valor antes de free
B. Ler após free se o endereço não mudou
C. Aumentar alocação
D. Testar alias!=NULL após free

**Resposta:** A. A cópia independente não depende mais do lifetime da alocação.

### 3. Por que a leitura pode parecer funcionar sem ASan?
A. free garante preservação
B. Heap é permanente
C. O compilador recria o objeto
D. Bytes podem não ter sido reutilizados, mas o acesso continua inválido

**Resposta:** D. A validade vem do lifetime, não do conteúdo residual.
