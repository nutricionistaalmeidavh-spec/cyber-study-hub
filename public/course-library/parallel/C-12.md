## Problema e objetivo

Crie uma sequência no heap dentro de uma função e use-a após a função retornar. Quem recebe o bloco passa a ser responsável por sua liberação; uma falha de alocação precisa ser prevista.

## Mecanismo e exemplo resolvido

malloc reserva bytes sem inicializá-los e devolve ponteiro ou NULL. O ponteiro local p termina com criar, mas o bloco alocado continua vivo até free. criar inicializa os três ints como 0,1,2 e transfere ownership ao chamador. A guarda SIZE_MAX/sizeof(int) evita overflow no cálculo de bytes; o exemplo didático usa n=3. Zero é recusado por contrato, sem depender das variações de malloc(0).

criar(3,0) → reserva 3*sizeof(int) bytes → inicializa 0,1,2 → retorna endereço → main lê → free encerra o bloco. criar(3,1) injeta NULL para exercitar o ramo de falha de modo determinístico; isso não alega ter provocado falta real de RAM.

```c
#include <assert.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
/* O chamador recebe ownership do bloco; precisa free uma vez. */
static int *criar(size_t n, int simular_falha) {
    if (n == 0 || n > SIZE_MAX / sizeof(int)) return NULL;
    /* injeção controlada testa o caminho de falha sem esgotar memória */
    int *p = simular_falha ? NULL : malloc(n * sizeof *p);
    if (p == NULL) return NULL;
    for (size_t i = 0; i < n; ++i) p[i] = (int)i;
    return p; /* o bloco vive além da chamada; o nome local p não */
}
int main(void) {
    int *dados = criar(3, 0);
    if (dados == NULL) { fputs("alocação falhou\n", stderr); return 1; }
    assert(dados[0] == 0 && dados[2] == 2);
    printf("heap: %d %d %d\n",dados[0],dados[1],dados[2]);
    free(dados);
    dados = NULL;
    assert(criar(3,1) == NULL && criar(0,0) == NULL);
    puts("falha simulada e tamanho zero tratados");
    return 0;
}
```

## Prática e autoexplicação

Parcial: mude n para 4 e identifique a inicialização do último elemento. Independente: desenhe uma função destruir que receba ponteiro e deixe claro se ela altera o nome do chamador. Autoexplicação: por que é válido devolver malloc, mas inválido devolver &variavel_local?

## Solução comentada e checkpoints

Quatro elementos seriam 0,1,2,3. free(dados) invalida o bloco; `dados=NULL` altera só esse nome. Uma função que zere o ponteiro do chamador precisaria receber endereço dele (int **), ou devolver NULL para atribuição. Checkpoints: falha não deve causar leitura; sucesso deve ter exatamente um free.

## Robustez, reteste e diagnóstico

Não tente simular falta de memória pedindo quantidades enormes. A injeção controlada cobre o ramo sem pressionar o host. Para n arbitrário, também limite a conversão de índice size_t para int ou use elementos size_t. Reteste sucesso, falha simulada e zero com sanitizers; nunca leia o bloco depois de free para “confirmar” a liberação.

O preenchimento converte índices para int; os índices usados no lab (0, 1 e 2) são representáveis. Para generalizar a tamanhos muito grandes, limite n de modo que cada índice caiba em int além de evitar overflow de n*sizeof(int).

## Quiz

1. **O bloco alocado termina quando:**
   - A) criar retorna
   - B) p sai de escopo
   - C) free é chamado

2. **malloc inicializa ints com zero?**
   - A) não
   - B) sempre
   - C) sim, quando malloc devolve memória nunca usada pelo programa

3. **A falha do lab é:**
   - A) esgotamento real
   - B) injeção controlada de NULL
   - C) retorno imprevisível provocado por ler memória sem inicializar

**Gabarito comentado:** 1: C — duração do bloco difere da duração do ponteiro local. 2: A — o programa precisa inicializar antes de ler. 3: B — é teste determinístico do caminho de erro.
