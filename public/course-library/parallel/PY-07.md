## Problema e objetivo

Ao converter entradas textuais, "x" é um erro de formato previsto; None é um defeito do chamador. Trate a primeira falha sem ocultar a segunda e demonstre que finally executa nos dois caminhos.

## Mecanismo e exemplo resolvido

try contém a operação que pode falhar. except ValueError trata somente a classe prevista. else executa se o try terminou sem exceção. finally executa antes de a função concluir, inclusive quando há return ou propagação. Um return dentro de finally poderia substituir o retorno anterior ou suprimir uma exceção: por isso o bloco somente registra finalização.

"12" → int=12 → else registra conversão → finally registra finalizado → retorna 12. "x" → ValueError → except registra formato → finally → retorna None. None → TypeError não capturado → finally → erro chega ao chamador.

```python
def converter(texto, trilha):
    try:
        numero = int(texto)
    except ValueError:  # texto inválido é uma falha prevista
        trilha.append("formato inválido")
        return None
    else:
        trilha.append("conversão concluída")
        return numero
    finally:
        trilha.append("finalizado")  # não faça return aqui: ocultaria o resultado/erro

if __name__ == "__main__":
    for entrada, esperado, eventos in [
        ("12", 12, ["conversão concluída", "finalizado"]),
        ("x", None, ["formato inválido", "finalizado"]),
    ]:
        trilha = []
        assert converter(entrada, trilha) == esperado
        assert trilha == eventos
        print(repr(entrada), esperado, trilha)
    trilha = []
    try:
        converter(None, trilha)  # TypeError: defeito do chamador; não esconder
    except TypeError:
        assert trilha == ["finalizado"]
        print("TypeError propagado; finally executado")
    else:
        raise AssertionError("TypeError foi ocultado")
```

## Prática e autoexplicação

Parcial: trace converter("0",trilha), distinguindo zero de None. Independente: teste converter(" 8 ",trilha) e converter("8.5",trilha). Autoexplicação: qual informação seria perdida ao substituir except ValueError por except Exception?

## Solução comentada e checkpoints

"0" retorna 0 e eventos de sucesso; " 8 " retorna 8 porque int aceita espaços; "8.5" retorna None com formato inválido porque não é representação de inteiro. Checkpoint: TypeError deve continuar visível ao chamador e a trilha desse caso deve conter apenas finalizado.

## Robustez, reteste e diagnóstico

Não use `if not resultado` para reconhecer o sentinela: zero também é falso. Use `resultado is None`. Não inclua operações sem relação no try, para não classificar erros de outras funções como formato inválido. Reteste os três caminhos fornecidos depois de alterar o tratamento. finally registra uma tentativa de finalização; para arquivos, prefira with para fechamento efetivo.

## Quiz

1. **converter("0",[]) devolve:**
   - A) 0
   - B) None
   - C) ValueError

2. **Qual erro atravessa a função?**
   - A) ValueError de "x"
   - B) nenhum por haver finally
   - C) TypeError de None

3. **Um return em finally pode:**
   - A) devolver um segundo resultado sem substituir o retorno anterior
   - B) ocultar erro pendente
   - C) preservar obrigatoriamente qualquer exceção anterior ao retorno

**Gabarito comentado:** 1: A — zero é inteiro válido. 2: C — except só trata ValueError. 3: B — o retorno substitui a propagação.

## Flashcards

- **except específico** → Recupera apenas falhas cujo significado foi previsto.
- **else do try** → Executa após try bem-sucedido.
- **finally** → Executa na saída normal, com retorno ou com exceção pendente.
