## Problema e objetivo

Dois ponteiros apontam para x=7. Uma função recebe o endereço e incrementa o objeto; explique por que x e a leitura pelo outro ponteiro passam a 8.

## Mecanismo e exemplo resolvido

`&x` obtém endereço do objeto; `p` armazena esse endereço; `*p` acessa o int ali armazenado. A passagem do ponteiro é por valor: a função recebe uma cópia do endereço, mas a dereferência alcança o mesmo objeto. Copiar p para alias não duplica x. NULL é um valor especial que não designa int acessível e deve ser rejeitado antes da dereferência.

Estado inicial x=7, p=&x, alias=&x. incrementar recebe o endereço e executa *p+=1; x=8 e *alias=8. incrementar(NULL) devolve 0 e não toca memória. O objeto x permanece vivo até main terminar; devolver endereço de uma variável automática local de uma função criaria ponteiro inválido após seu retorno.

```c
#include <assert.h>
#include <stdio.h>
/* Ponteiro emprestado: chamador mantém o objeto vivo durante a chamada. */
static int incrementar(int *p) {
    if (p == NULL) return 0; /* NULL não aponta para um int válido */
    *p += 1;               /* grava no objeto apontado */
    return 1;
}
int main(void) {
    int x = 7;
    int *p = &x;           /* & obtém endereço; ainda não copia x */
    int *alias = p;        /* ambos designam o mesmo x */
    assert(incrementar(p));
    assert(x == 8 && *alias == 8);
    assert(!incrementar(NULL));
    printf("x=%d alias=%d null=recusado\n",x,*alias);
    return 0;             /* lifetime de x termina na saída de main */
}
```

## Prática e autoexplicação

Parcial: faça segunda chamada incrementar(alias) e preveja x. Independente: escreva zerar(int *destino) com o mesmo tratamento de NULL. Autoexplicação: reatribuir o parâmetro p para NULL dentro da função mudaria o p do chamador?

## Solução comentada e checkpoints

Segunda chamada produz x=9. zerar pode testar NULL, escrever *destino=0 e devolver 1. Reatribuir apenas o parâmetro ponteiro não muda o nome no chamador: ele também é passado por valor. Checkpoint: diferencie mudança do endereço armazenado de mudança no objeto apontado.

## Robustez, reteste e diagnóstico

Um ponteiro não nulo ainda pode estar pendente, desalinhado ou fora do objeto; NULL não é validação completa. O contrato de lifetime é responsabilidade conjunta de quem empresta e de quem usa. Não retorne &local. Reteste objeto vivo e NULL; se alias mostrar valor diferente de x, revise se ambos ainda designam o mesmo objeto.

O contrato deste incremento também exige `*p < INT_MAX`: validar NULL não evita overflow aritmético nem comprova que um ponteiro não nulo ainda esteja vivo. O caso fornecido usa x=7; não generalize a segurança a qualquer endereço/valor.

## Quiz

1. **Depois de incrementar(p), *alias vale:**
   - A) 7
   - B) 8
   - C) endereço de x

2. **Qual operação lê o objeto apontado?**
   - A) &p
   - B) p = NULL
   - C) *p

3. **NULL aceito sem erro exigiria:**
   - A) não dereferenciá-lo
   - B) copiar NULL para outro ponteiro antes do acesso
   - C) testar somente se o endereço foi inicializado com NULL

**Gabarito comentado:** 1: B — os ponteiros compartilham o objeto. 2: C — dereferência acessa o destino. 3: A — não há int acessível por NULL.
