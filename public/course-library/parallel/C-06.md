## Problema e objetivo

Some o array {4,7,2} sem acessar posição inexistente. Você deve relacionar capacidade, índice e quantidade percorrida, inclusive a chamada vazia.

## Mecanismo e exemplo resolvido

Um array contém elementos contíguos do mesmo tipo. Para três ints, índices válidos são 0,1,2; índice 3 está fora. sizeof valores mede bytes do array no escopo da declaração; dividir por sizeof valores[0] obtém 3 elementos. Ao passar à função, o parâmetro é ponteiro: a quantidade n precisa viajar separada, pois sizeof do ponteiro não recupera a capacidade.

Traço do acumulador: antes do laço total=0; i=0 soma 4 →4; i=1 soma 7 →11; i=2 soma 2 →13; i=3 falha i<n e termina. Em soma(NULL,0), a condição é falsa no primeiro teste e nenhum endereço é acessado.

```c
#include <assert.h>
#include <stddef.h>
#include <stdio.h>
/* n é quantidade de elementos, não bytes; acesso só ocorre para i < n. */
static int soma(const int *valores, size_t n) {
    int total = 0;
    for (size_t i = 0; i < n; ++i) total += valores[i];
    return total;
}
int main(void) {
    int valores[] = {4, 7, 2};
    size_t n = sizeof valores / sizeof valores[0];
    assert(n == 3 && soma(valores, n) == 13);
    assert(soma(NULL, 0) == 0); /* corpo não acessa NULL */
    printf("n=%zu soma=%d vazio=%d\n", n, soma(valores,n), soma(NULL,0));
    return 0;
}
```

## Solução comentada e checkpoints

Nova soma 16. Para maior, n=0 pode retornar 0 sem escrever saída; n>0 inicializa máximo com valores[0], compara de i=1 até n-1 e retorna 1. Checkpoint: quantidade zero deve evitar toda dereferência, não apenas devolver zero depois de ler valores[0].

## Robustez, reteste e diagnóstico

Não declare array de tamanho zero como se fosse C padrão. O exemplo vazio é ponteiro NULL com comprimento zero. O chamador deve garantir n dentro da capacidade; a função não pode descobri-la sozinha. Soma pode ultrapassar int para dados arbitrários: o fixture usa totais pequenos. Reteste n=0,1,3 e revise qualquer warning de conversão.

Este exemplo usa inteiros pequenos: o acumulador `int` pressupõe que cada soma caiba no tipo. Um vetor arbitrário exige validar overflow; passar n maior que a quantidade real continua inválido.
